## 这是什么

小红书上不缺经验，缺的是让人知道"这段经验在什么条件下成立、能不能试、下一步先做什么"。

Experience Card 把一段真实经历，通过五个结构化问题整理成一张"经验卡"：前提、动作、结果、适用对象、边界。作者确认后公开，读者输入自己的情境，AI 给出适配判断和一个低风险的"微行动"，试用后的反馈会回到作者手上，推动经验迭代。

```
真实经历 → 五问追问 → AI整理 → 作者确认 → 公开发布 → 读者输入情境 → 适配判断+微行动 → 反馈回流 → 经验迭代
```

三个板块：
- **经验广场**：发现、搜索、试用经验
- **社区**：围绕试用和反馈互动
- **个人经验名片**：展示作者和经验集合，创建经验卡也在这里；像素头像和实时互动是视觉记忆点，不是核心价值

## 技术架构

```
React/Vite 前端
 ├─ Supabase Auth（注册/登录/回调）
 ├─ Supabase Postgres + RLS（卡片/草稿/公开状态/反馈/版本权限）
 ├─ Supabase Storage（图片、像素资产）
 └─ Supabase Edge Functions（密钥保护、调用 Dify、输入输出校验）
      └─ Dify Workflow（经验编译器 + 情境试用器）

Cloudflare Pages / Functions：正式网页、图片接口、二维码与下载
浏览器端 MediaPipe：本地处理摄像头图像生成像素头像，原始画面不上传给模型
```

## 做了什么，明确没做什么

**已完成**：经验广场、五问创建、AI 生成经验卡（Dify）、作者确认与发布门禁、情境试用、反馈回流、个人经验名片、像素头像、二维码/分享下载、Supabase 权限（GRANT + RLS）、Cloudflare 生产部署。

**明确没做**（本届边界，不做过度包装）：小红书官方 API 接入、自动抓取、自动发帖、RED Skill 云端插件；招聘/交易/自动匹配等泛社交功能；多 Agent 系统——当前是两个受约束的 Dify Workflow（经验编译器 + 情境试用器），不是具备长期记忆和自主规划的成熟 Agent。
